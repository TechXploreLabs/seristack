seristack

Shell workflows in YAML. CLI, HTTP, and MCP from one config.

Seristack is a CLI tool that runs shell workflows defined in YAML. The same workflows can be served over HTTP with per-stack authorization, or exposed as MCP tools for AI agents and IDEs.

Watch the demo Quick start Examples

Features

  • Many command stacks in one YAML file
  • Four execution modes, with repeat counts
  • Dependencies between stacks
  • Variables with validation rules
  • Share output between stacks
  • HTTP endpoints with per-stack access rules
  • Structured JSON audit log
  • MCP server: stdio, SSE, streamableHTTP
  • Per-command timeouts that stop child processes too
  • Built-in shell, or Bash, PowerShell, Python, and others

Why Seristack?

One stack, three interfaces

The same YAML stack runs as a CLI command, an internal HTTP API, or an MCP tool.

Scripts without a backend

Wrap existing shell scripts and runbooks without writing a web service for each one.

MCP from YAML

Give AI tools safe, named operations without hand-coding an MCP server.

Access rules per stack

Restrict who can run what using identity headers set by your authenticating proxy.

See it in action

Running stacks through the CLI, the HTTP API, and the MCP server with an AI agent.

Linux

curl -fsSL https://raw.githubusercontent.com/TechXploreLabs/seristack/main/install.sh | bash

Windows (PowerShell)

irm https://raw.githubusercontent.com/TechXploreLabs/seristack/main/install.ps1 | iex

Prefer a binary? Download one for Linux, macOS, or Windows from GitHub Releases, extract it, and put seristack on your PATH.

Quick start

1. Write a config

stacks:
  - name: build
    count: 1
    cmds:
      - echo "building..."

  - name: test
    count: 1
    dependsOn: [build]
    cmds:
      - echo "testing..."

A stack with count: 0 is skipped, so set count: 1 to run once.

2. Run it three ways

seristack trigger -c config.yaml                # CLI: run once
seristack run -c config.yaml                    # HTTP: serve stacks as endpoints
seristack mcp -t streamableHTTP                 # MCP: serve stacks as AI tools

Add method and urlPath to serve a stack over HTTP. Add a description to expose it as an MCP tool.

More in the examples and the config reference.

Security

Seristack runs shell commands with the permissions of the user who starts it, and it is not a sandbox. It serves plain HTTP with no built-in authentication or TLS. Keep it on 127.0.0.1 behind a reverse proxy such as nginx or Caddy, and never expose it directly to the internet.

Proxy handles identity

The proxy terminates TLS, authenticates users, removes client-supplied identity headers, and sets its own. Seristack authorizes each stack from those headers.

Stacks without rules are open

A stack with no access block has no stack-level restriction. Add rules to every sensitive stack.

Validate every input

Callers can only set declared variables. Use allowed_value and anchored allowed_regex rules, because values are substituted into commands.

Audit log

Every execution can be logged as JSON. Mark secrets sensitive: true to keep them out of it, and prefer reading secrets from the environment in your scripts.
