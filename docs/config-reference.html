Root object

Seristack configs are YAML files with a root stacks list.

stacks:
  - name: example
    cmds:
      - echo "hello from seristack"
AttributeTypeRequiredDescription
stackslistyesList of stack/workflow definitions.

Variables and validation

Variables can be used in commands with {{.Vars.variable_name}}.

vars:
  - name: env
    value: dev
    required: true
    allowed_value: [dev, stage, prod]
AttributeTypeRequiredDescription
namestringyesVariable name. Must be unique within the stack.
valuestringnoDefault variable value.
requiredbooleannoFinal value must not be empty.
allowed_valuelistnoAllows only listed values.
denied_valuelistnoRejects listed values.
allowed_regexstringnoAllows only values matching regex(...).
denied_regexstringnoRejects values matching regex(...).

Only one of allowed_value, denied_value, allowed_regex, or denied_regex can be used per variable. required can be combined with one of them.

Do not pass secrets as stack vars. They will appear in the audit log and in slog output. Secrets should come from environment variables or a secrets manager inside the shell script.

Runtime values can come from CLI flags, HTTP query/form/JSON body, HTTP X-* headers, and MCP tool arguments.

Shell settings

If shell is omitted, Seristack uses the built-in mvdan shell interpreter. External shells can be configured with shell and shellArg.

shell: bash
shellArg: -c

HTTP endpoint behavior

A stack becomes an HTTP endpoint when method is set.

name: deploy
method: POST
urlPath: /deploy

HTTP variables can come from query parameters, form values, JSON request body, and headers beginning with X-.

# query param
curl "http://127.0.0.1:8080/deploy?env=staging"

# JSON body
curl -X POST http://127.0.0.1:8080/deploy \
  -H "Content-Type: application/json" \
  -d '{"env": "staging", "version": "v1.2.3"}'

Authorization (HTTP)

The access block restricts which users or groups can execute an HTTP stack endpoint. Seristack reads identity headers forwarded by nginx or Caddy after they validate the user against your IdP.

HTTP only. The access and matchAccess fields apply to HTTP endpoints only. MCP tool calls bypass this check. Secure MCP at the transport level using nginx, Caddy, or network policy.

Basic usage

stacks:
  - name: deploy
    method: POST
    urlPath: /deploy
    matchAccess: ANY
    access:
      - headerName: "X-Auth-Request-Groups"
        headerValue: ["sre", "platform"]
      - headerName: "X-Auth-Request-Roles"
        headerValue: ["admin"]
    cmds:
      - ./deploy.sh

access rule attributes

AttributeTypeRequiredDescription
headerNamestringyesThe exact HTTP header name to read. Must match what nginx or Caddy forwards.
headerValuelistyesAllowed values. Access granted if the header contains any of these values. Comma-separated header values are split automatically.

matchAccess values

ValueBehaviour
ANYAccess granted if any one rule matches. Default.
ALLAccess granted only if every rule matches.

Examples

# Any member of sre or platform can run
access:
  - headerName: "X-Auth-Request-Groups"
    headerValue: ["sre", "platform"]

# Must be in devops AND have admin role
matchAccess: ALL
access:
  - headerName: "X-Auth-Request-Groups"
    headerValue: ["devops"]
  - headerName: "X-Auth-Request-Roles"
    headerValue: ["admin"]

# Specific user only
access:
  - headerName: "X-Auth-Request-Email"
    headerValue: ["oncall@company.com"]

Testing without nginx (local development)

Pass identity headers directly in curl while developing locally:

# Granted — group matches
curl -X POST http://127.0.0.1:8080/deploy \
  -H "X-Auth-Request-Groups: sre" \
  -H "Content-Type: application/json" \
  -d '{"env": "staging"}'

# Denied — group not in access block
curl -X POST http://127.0.0.1:8080/deploy \
  -H "X-Auth-Request-Groups: intern" \
  -H "Content-Type: application/json" \
  -d '{"env": "staging"}'

Audit log

Enable a structured JSON audit trail for every HTTP stack execution via CLI flags:

seristack run \
  --audit-log /var/log/seristack/audit.log \
  --identity-header "user=X-Auth-Request-Email" \
  --identity-header "groups=X-Auth-Request-Groups" \
  --identity-header "roles=X-Auth-Request-Roles"

Every execution writes one JSON line:

{
  "timestamp": "2024-01-15T10:30:00Z",
  "event": "stack_executed",
  "stack": "deploy",
  "path": "/deploy",
  "method": "POST",
  "source_ip": "127.0.0.1:54231",
  "identity": {
    "user": "alice@company.com",
    "groups": "sre,platform"
  },
  "vars": {"env": "staging", "version": "v1.2.3"},
  "success": true,
  "duration_ms": 1423
}

Query with jq:

# All failures
jq 'select(.success == false)' /var/log/seristack/audit.log

# Everything a specific user ran
jq 'select(.identity.user == "alice@company.com")' /var/log/seristack/audit.log

# Slow executions over 30s
jq 'select(.duration_ms > 30000)' /var/log/seristack/audit.log

MCP tool behavior

A stack becomes an MCP tool when description is set. Variables declared in vars become MCP tool arguments.

The access block does not apply to MCP tool calls. MCP access is controlled at the transport level — put nginx or Caddy in front of the MCP server port and restrict by network, token, or IP.

Complete example

stacks:
  - name: deploy
    description: Deploy the application to a target environment
    method: POST
    urlPath: /deploy
    matchAccess: ANY
    access:
      - headerName: "X-Auth-Request-Groups"
        headerValue: ["sre", "platform"]
      - headerName: "X-Auth-Request-Roles"
        headerValue: ["admin"]
    count: 1
    timeouts: 10m
    executionMode: SEQUENTIAL
    vars:
      - name: env
        value: staging
        required: true
        allowed_value: [staging, production]
      - name: version
        required: true
        allowed_regex: regex("^[a-zA-Z0-9._-]+$")
    cmds:
      - |
        echo "Deploying {{.Vars.version}} to {{.Vars.env}}"
        kubectl set image deployment/app app={{.Vars.version}}

  - name: collect-metadata
    description: Produces JSON metadata for aggregation
    dependsOn: [deploy]
    count: 2
    timeouts: 5m
    executionMode: SEQUENTIAL
    vars:
      - name: env
        value: staging
    cmds:
      - |
        echo "{\"index\": {{.Count.index}}, \"env\": \"{{.Vars.env}}\", \"status\": \"ok\"}"
    output: |
      echo '{{.Self.result}}' | grep "^{" | jq -s '{records: ., total: length}'

  - name: cleanup
    dependsOn: [collect-metadata]
    discardOutput: [deploy]
    count: 1
    timeouts: 10s
    cmds:
      - echo "discarded deploy output from memory"

Start the server with audit logging enabled:

seristack run \
  --config config.yaml \
  --addr 127.0.0.1 \
  --port 8080 \
  --audit-log /var/log/seristack/audit.log \
  --identity-header "user=X-Auth-Request-Email" \
  --identity-header "groups=X-Auth-Request-Groups"
